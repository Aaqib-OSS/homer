# Security Policy

## Supported Versions

Only the latest release is supported with security fixes.

## Reporting a Vulnerability

Please report security vulnerabilities privately through GitHub's
**Report a vulnerability** form:
https://github.com/livesport/homer/security/advisories/new. Do not open
public issues for security reports.

There is no bug bounty program.

## Accepted risks

Weaknesses a scanner will legitimately keep reporting, which the maintainers
have consciously decided not to fix. Each row names the decision record that
argues the trade-off — the ADR is the authority, this table is the index.

Record a risk here **at the same time** as the decision, not when a scanner
first raises it: the security intake automation reads this file and
`docs/adr/` to avoid opening a ticket for something already settled. A new
row takes the next free `AR-NN` id; an id is never reused, so code can cite
it ([ADR-0117](docs/adr/0117-code-says-what-adrs-say-why.md)).

| AR-01 | The output cap counts kept bytes, not raw process output: a command whose output is entirely dropped by `claudeDropSystemSubtypes` cannot trip `maxOutputBytes` (CWE-770, CVSS 5.3) | `LineFilteringOutputStream`, all four `ShellExecutor` backends | [ADR-0063](docs/adr/0063-filter-claude-stdout-at-write-time.md) | The run stays bounded by its `timeout` and the filter's memory is constant, so the failure mode is bounded CPU and I/O rather than exhaustion. | AR-02 | A Claude session with more than 1 000 model calls is charged the spend endpoint's best figure observed at poll time while its later calls remain unpriced, so the recorded cost can understate actual spend (CWE-693/CWE-400, CVSS 2.3) | `LlmHarnessExecutor.accountAttempt` capped-poll branch | [ADR-0061](docs/adr/0061-price-claude-runs-from-session-spend-endpoint.md), amendment 2026-09-16 | Every session figure priced from a capped poll is forced to an `incomplete:` `fallbackReason`, visible in the status API and spans, so the under-count is never silent, and no path charges below the best session figure observed. Lifting the cap would let crafted stdout drive the full poll schedule. Reaching the path needs an authenticated Claude run and favorable ingestion lag. |
| AR-04 | An ancestor directory of a packed file can be swapped for a symlink between the pack walk's containment check and `addFile`'s by-name open, so a file outside the upload root can enter a downloaded archive; on `homer-runner` the download's root itself can be swapped so between its realpath check and the pack (same-UID TOCTOU; `NOFOLLOW_LINKS` binds only the final component) (CWE-59/CWE-367, CVSS 2.3) | `TarStreams.addDirContents` + `TarStreams.addFile` (pack path, all transports); `WorkspaceSync.uploadDirInto` + `uploadFile` (ssh SFTP upload); `SessionWorkspace.contained`, then `TarStreams.pack` (`homer-runner` download) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-09-23 | No principal is crossed: the race needs a concurrent writer holding the runner's own UID, which can already read every file it could disclose. Closing it needs an `openat`-style dirfd walk plus an `fstat` on the opened handle, neither of which `java.nio` exposes portably (ADR-0047 rule 6). Escaping symlinks are skipped, the walk descends on the checked realpath, hard links are skipped, so the exposure is confidentiality-only at the runner's own UID. |
| AR-05 | A target or ancestor directory of an extracted file can be swapped for a symlink between the extract walk's containment check and its by-name open, so sync-down can write a file outside the workspace; on `homer-runner` the upload's target itself can be swapped so between its realpath check and the extract (same-UID TOCTOU; the directory branch must follow contained links) (CWE-59/CWE-367, CVSS 5.8) | `TarStreams.extractEntry` directory branch (Kubernetes sync-down, external-runner tar download); `SessionWorkspace.contained`, then `TarStreams.extract` (`homer-runner` upload) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-09-30 | No principal is crossed: the tar stream cannot create links (link entries are skipped), so the race needs a concurrent writer holding Homer's own UID, which can already write every file it could reach. The single-file branch writes with `NOFOLLOW_LINKS`; its own residual, the mode normalization, is the next row. |
| AR-06 | A single-file download's target can be swapped for a symlink between the `NOFOLLOW_LINKS` write and the mode normalization, which the JDK applies to the link's destination even through a `NOFOLLOW_LINKS` view, so the destination's mode becomes `0755` or `0644` (same-UID TOCTOU) (CWE-59/CWE-367) | `TarExtraction.extractEntry` single-file branch (Kubernetes and external-runner single-file download) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-11-05 | No principal is crossed: the race needs a concurrent writer holding Homer's own UID, which can already change the mode of every file the link could lead to; the write itself still refuses a link. Closing it needs an `fchmod` on the write's descriptor, which `java.nio` does not expose; creating the file with its final mode is defeated by the umask and by an overwritten file keeping its mode. |
| AR-07 | A caller cancelled while a LangGraph inspect/state interpreter runs keeps its permit, the child and its readers until the child exits or the 15 s timeout fires, because the wait is one blocking `waitFor` (CWE-772, CVSS 5.3) | `runBoundedGraphSubprocess` (`ProcessGraphInspectRunner`, `ProcessGraphStateRunner`) | [ADR-0073](docs/adr/0073-langgraph-topology-is-structured-data.md), amendment 2026-10-09 | Cancellation gives no amplification: an uncancelled caller holds the same single permit and interpreter for the same bounded time. Total work stays capped by the four permits per service and the 5 s queue shed, which cancellation cannot bypass, and the process-group reap still runs when the wait returns. No confidentiality or integrity impact; reaching the path needs an authenticated grant. |
| AR-08 | A deeply nested brace pattern exhausts the stack while `braces` compiles it, so whoever shapes a glob pattern can stall the process (CWE-674, CVSS 8.7) | `braces` 3.0.3 ← `micromatch` 4.0.8 ← `fast-glob` 3.3.1 ← `@next/eslint-plugin-next`, dev-only lint toolchain | [ADR-0088](docs/adr/0088-dependency-check-on-the-nvd-mirror.md), amendment 2026-10-17 | No patched `braces`, `micromatch`, `fast-glob` or `@next/eslint-plugin-next` release exists yet, and the package is a transitive development dependency, so it ships in no image (the console image carries only the `.next/standalone` trace). The only patterns it compiles are the repository's own ESLint globs — repository-controlled input, never untrusted data — so no principal is crossed. Revisit when a fixed release ships. |
| AR-09 | The ssh runner puts a command's merged env, secrets included, on the remote command line as `env K=V…` arguments, so another user of the remote host who reads its process table while the login shell and `env` start the command, or any `execve` auditing there, sees every value (CWE-214) | `RemoteCommandBuilder.build` and `buildReaping` (ssh runner, every command) | [ADR-0032](docs/adr/0032-ssh-runner-backend.md), amendment 2026-11-20 | **Interim; this row grants no exception to [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md) rule 7.** [#364](https://github.com/livesport/homer/issues/364) delivers the env as a sourced file and removes this row. Until then: the process-table read is bounded to the launch, because the shell `exec`s `env`, which `exec`s the command, so the values leave the process table once the command starts and remain only in its environment, which other users cannot read; Linux `hidepid=2` on `/proc` closes that read. `execve` audit records keep the argv for as long as the remote host retains them, under that host's root and outside Homer's control. The remote host and its other users are the operator's choice, outside Homer's principals; [`app/SERVER.md`](app/SERVER.md) tells operators to keep secrets out of `env` on multi-tenant hosts. Context only: many sshd configurations reject `SendEnv`, the ssh protocol's own env channel. |
| AR-10 | The Kubernetes runner passes a command's merged env, secrets included, as `env K=V…` arguments in the exec request's `command=` query parameters, so the request URI carries every value; Kubernetes audit events record `requestURI` at every level, `Metadata` included, so a cluster that audits `pods/exec` stores the values in its audit backend (CWE-598/CWE-532) | `KubernetesShellExecutor.cmd` env prefix, sent by `KubernetesApiExecClient` (Kubernetes runner, every command) | [ADR-0043](docs/adr/0043-k8s-sync-workspaces.md), [ADR-0045](docs/adr/0045-external-secret-delivery.md) | **Interim; this row grants no exception to [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md) rule 7.** [#364](https://github.com/livesport/homer/issues/364) delivers the env as a sourced file and removes this row. Until then: the reader is whoever can read the cluster's audit backend and any log pipeline it ships to. That reader is not a Homer principal, and caller-supplied `secret` inputs reach it along with operator env. The URI travels over TLS into no stored Kubernetes object, and [`app/SERVER.md`](app/SERVER.md) tells operators to scope the `pods/exec` audit policy. Inside Homer, a lost channel's step error and the exec client's failure log drop the exec URL and carry no cause or stack trace that quotes it; env values of at least 8 characters, raw and URL-encoded, are masked wherever else that text quotes them. A secret that must stay out of the URI already has a route: file delivery from cluster tooling, which Homer never sees (ADR-0045). |
| AR-11 | A component below `remoteWorkspaceRoot` can be swapped for a symlink between the ssh cleanup's per-component `lstat` checks and the `rm -rf` (or its SFTP fallback walk), which resolves the path again, so the sweep can delete a directory outside the workspace that the ssh user can write (same-UID TOCTOU) (CWE-59/CWE-367) | `SshRunnerSession.cleanWorkspace` (`rm -rf` over the exec channel, `WorkspaceSync.removeRecursively` fallback) | [ADR-0067](docs/adr/0067-ssh-cleanup-via-rm-rf.md) | No principal is crossed: the race needs a concurrent writer holding the ssh user's own UID on the remote host, a process the run left behind or another tenant of that account, which can already delete everything the sweep could reach. Closing it needs the removal anchored on a directory handle checked once, which neither `rm` on a path argument nor path-based SFTP operations provide. `remoteWorkspaceRoot` is checked at config load (absolute, normalized, not `/`); before the sweep the project root must also be at least two segments deep and below it. A symlink the `lstat`s find refuses the sweep, and the removal runs with the ssh user's own permissions. |
| AR-12 | A symlink swapped in for the artifacts directory between its check and `readTextBounded`'s open of `langgraph.json` or a watched run's stdout makes Homer read a different regular file than the one it checked, at most 64 KiB (4 MiB for a by-reference result fetch); when it parses as a run identity, the status endpoint reports its `threadId`, `module` and `segment` and a resume continues its thread, and a firing continuation or a by-reference result fetch delivers it as the watched run's result. The artifact download, the log tail and the LLM-event stream check the artifacts directory only when they resolve the path and open the file later (a stream at the first poll that finds it, as late as the stream's end), so a symlink swapped in for the directory in between is followed and the caller is served the file it leads to. A symlink at the run root or a directory above it is followed by every one of these reads with no race at all (same-UID; `O_NOFOLLOW` binds only the final component) (CWE-59/CWE-367) | `LocalFileOperations.readTextBounded`, called by `LangGraphRunStatusService.identity` for `GET /api/v1/processes/{id}/langgraph` and `POST /api/v1/processes/{id}/resume`, and by `ContinuationFireService.extractResult` when a continuation fires; `ArtifactService.resolveArtifactPath`, then `readTextBounded` (`GET /api/v1/callback/results/{token}`); `ArtifactService.resolveArtifactPath`, then `LocalFileOperations.streamFile` (artifact download); `LogTailService.resolve`, then `tail`; `LlmEventStreamService.resolve`, then `followFile` | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendments 2026-11-20 and 2026-11-21 | No principal is crossed and nothing is gained: each case needs a local writer holding Homer's own UID, such as a local run's own code, which can already read any file the swap could lead to and copy its content into the run's own files directly. Those files are agent-written, so their content is attacker-chosen by construction (ADR-0047 rule 2), and a swap only changes where it comes from. Homer acts on an identity read, but both callers keep the thread id inside the run owner's checkpoint store, so neither the status read nor the resumed run reaches another principal's checkpoints ([ADR-0046](docs/adr/0046-owner-scoped-langgraph-checkpoints.md)); a continuation's result is the watched run's own output, which that run could have written anyway, and a download or stream answers only a caller who may already see the run. Every one of these reads opens the file with `O_NOFOLLOW` and `O_NONBLOCK` and checks the opened descriptor, and the streams then follow that descriptor alone, so a symlink, hard link, FIFO or other non-regular file at the final component is refused whenever it was swapped in, and no open blocks; closing the directory swaps needs an `openat`-style walk from a descriptor on the checked directory, and re-checking the directory at each poll would only narrow the streams' window; checking the run root and above needs the configured workspace root, which an operator may reach through a symlink, so a stored artifacts path cannot be compared with it lexically. A symlinked artifacts directory found at resolve, or a symlinked `langgraph.json` or stdout file, is refused, as is a recorded stdout path outside the artifacts directory, and the read stops at `MAX_IDENTITY_BYTES`, the 64 KiB inline-result cap or the 4 MiB transform cap. |
| AR-13 | Code an `edit` holder writes runs on the server host as Homer's own user — an agent routed to the `local` runner, or the LangGraph inspect/state interpreter importing the agent's graph module — and can read operator secrets beyond `agentSysEnvAllowlist`: everything Homer's user can read (the config file, the database, other runs' workspaces, ssh keys and kubeconfigs the server uses), the environment of concurrent runs, and, where the server JVM stays dumpable, the server's own environment (CWE-269/CWE-214) | `local`-runner runs and `homer_langgraph inspect`/`state` subprocesses; `hardenServerJvm` on a host without `prctl` or when the call fails | [ADR-0037](docs/adr/0037-grants-authorization.md), [ADR-0078](docs/adr/0078-runner-jvm-is-non-dumpable.md), amendments 2026-11-21 | The principal crossing is real: an `edit` holder is not the operator. `edit` is documented as authority over what the agent runs, and closing the remainder needs a per-run uid or a sandbox, which ADR-0078 found unavailable under the pod policy. On Linux the server JVM is non-dumpable, so its environment and ptrace are denied; a failed call is logged at ERROR. That covers only the copy the JVM holds: the images `exec` the JVM, but a host launcher that stays alive as Homer's user (a shell wrapper without `exec`, `gradle run`) keeps the environment readable. A dumpable server remains on macOS, which is for development, where the developer is the operator. The operator's mitigations: grant `edit` only to principals trusted with what Homer's user can read, turn the `local` runner off (`server.localRunner.enabled: false`) where agents need not run beside the server, and keep secrets out of files Homer's user can read; the server's own environment is the protected place on Linux. |
