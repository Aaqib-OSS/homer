# Security Policy

## Supported Versions

Only the latest release is supported with security fixes.

## Reporting a Vulnerability

Please report security vulnerabilities privately through GitHub's
**Report a vulnerability** form:
https://github.com/livesport/homer/security/advisories/new. Do not open
public issues for security reports.

There is no bug bounty program.

## Accepted risks

Weaknesses a scanner will legitimately keep reporting, which the maintainers
have consciously decided not to fix. Each row names the decision record that
argues the trade-off — the ADR is the authority, this table is the index.

Record a risk here **at the same time** as the decision, not when a scanner
first raises it: the security intake automation reads this file and
`docs/adr/` to avoid opening a ticket for something already settled. A new
row takes the next free `AR-NN` id; an id is never reused, so code can cite
it ([ADR-0117](docs/adr/0117-code-says-what-adrs-say-why.md)).

| AR-01 | The output cap counts kept bytes, not raw process output: a command whose output is entirely dropped by `claudeDropSystemSubtypes` cannot trip `maxOutputBytes` (CWE-770, CVSS 5.3) | `LineFilteringOutputStream`, all four `ShellExecutor` backends | [ADR-0063](docs/adr/0063-filter-claude-stdout-at-write-time.md) | The run stays bounded by its `timeout` and the filter's memory is constant, so the failure mode is bounded CPU and I/O rather than exhaustion. Counting raw bytes would kill the runs the filter exists to keep alive. No confidentiality or integrity impact; reaching the path needs an authenticated `Action.RUN`. |
| AR-02 | A Claude session with more than 1 000 model calls is charged the spend endpoint's best figure observed at poll time while its later calls remain unpriced, so the recorded cost can understate actual spend (CWE-693/CWE-400, CVSS 2.3) | `LlmHarnessExecutor.accountAttempt` capped-poll branch | [ADR-0061](docs/adr/0061-price-claude-runs-from-session-spend-endpoint.md), amendment 2026-09-16 | Every session figure priced from a capped poll is forced to an `incomplete:` `fallbackReason`, visible in the status API and spans, so the under-count is never silent, and no path charges below the best session figure observed. Lifting the cap would let crafted stdout drive the full poll schedule. Reaching the path needs an authenticated Claude run and favorable ingestion lag. |
| AR-03 | The one-shot E2E runner receives the Artifactory read credentials as container environment, visible to `docker inspect` and to every process in the container for its lifetime (CWE-526, CVSS 4.8) | `docker-compose.e2e.yml` `e2e-runner.environment` | [`DOCKER.md`](DOCKER.md) § Artifactory build secrets | No principal is crossed: the CI job that holds the pair starts the container itself, and the container runs this repo's own test suite, not agent code. A `/run/secrets` file plus an entrypoint shim would only hide the pair from `docker inspect` / `docker exec`, which need root-equivalent daemon access that can read the secret file or `/proc/1/environ` anyway; Gradle's test workers inherit the shim's env, so in-container code still sees it. Revisit if the runner ever executes untrusted code. |
| AR-04 | An ancestor directory of a packed file can be swapped for a symlink between the pack walk's containment check and `addFile`'s by-name open, so a file outside the upload root can enter a downloaded archive (same-UID TOCTOU; `NOFOLLOW_LINKS` binds only the final component) (CWE-59/CWE-367, CVSS 2.3) | `TarStreams.addDirContents` + `TarStreams.addFile` (pack path, all transports); `WorkspaceSync.uploadDirInto` + `uploadFile` (ssh SFTP upload) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-09-23 | No principal is crossed: the race needs a concurrent writer holding the runner's own UID, which can already read every file it could disclose. Closing it needs an `openat`-style dirfd walk plus an `fstat` on the opened handle, neither of which `java.nio` exposes portably (ADR-0047 rule 6). Escaping symlinks are skipped, the walk descends on the checked realpath, hard links are skipped, so the exposure is confidentiality-only at the runner's own UID. |
| AR-05 | A target or ancestor directory of an extracted file can be swapped for a symlink between the extract walk's containment check and its by-name open, so sync-down can write a file outside the workspace (same-UID TOCTOU; the directory branch must follow contained links) (CWE-59/CWE-367, CVSS 5.8) | `TarStreams.extractEntry` directory branch (Kubernetes sync-down, external-runner tar download) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-09-30 | No principal is crossed: the tar stream cannot create links (link entries are skipped), so the race needs a concurrent writer holding Homer's own UID, which can already write every file it could reach. Closing it needs an `openat`-style dirfd walk plus `fstat`, which `java.nio` does not expose portably; a point-of-use re-check only narrows the window and costs a realpath walk per entry. The single-file branch writes with `NOFOLLOW_LINKS`; its own residual, the mode normalization, is the next row. |
| AR-06 | A single-file download's target can be swapped for a symlink between the `NOFOLLOW_LINKS` write and the mode normalization, which the JDK applies to the link's destination even through a `NOFOLLOW_LINKS` view, so the destination's mode becomes `0755` or `0644` (same-UID TOCTOU) (CWE-59/CWE-367) | `TarExtraction.extractEntry` single-file branch (Kubernetes and external-runner single-file download) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-11-05 | No principal is crossed: the race needs a concurrent writer holding Homer's own UID, which can already change the mode of every file the link could lead to; the write itself still refuses a link. Closing it needs an `fchmod` on the write's descriptor, which `java.nio` does not expose; creating the file with its final mode is defeated by the umask and by an overwritten file keeping its mode. |
| AR-07 | A caller cancelled while a LangGraph inspect/state interpreter runs keeps its permit, the child and its readers until the child exits or the 15 s timeout fires, because the wait is one blocking `waitFor` (CWE-772, CVSS 5.3) | `runBoundedGraphSubprocess` (`ProcessGraphInspectRunner`, `ProcessGraphStateRunner`) | [ADR-0073](docs/adr/0073-langgraph-topology-is-structured-data.md), amendment 2026-10-09 | Cancellation gives no amplification: an uncancelled caller holds the same single permit and interpreter for the same bounded time. Total work stays capped by the four permits per service and the 5 s queue shed, which cancellation cannot bypass, and the process-group reap still runs when the wait returns. No confidentiality or integrity impact; reaching the path needs an authenticated grant. |
| AR-08 | A deeply nested brace pattern exhausts the stack while `braces` compiles it, so whoever shapes a glob pattern can stall the process (CWE-674, CVSS 8.7) | `braces` 3.0.3 ← `micromatch` 4.0.8 ← `fast-glob` 3.3.1 ← `@next/eslint-plugin-next`, dev-only lint toolchain | [ADR-0088](docs/adr/0088-dependency-check-on-the-nvd-mirror.md), amendment 2026-10-17 | No patched `braces`, `micromatch`, `fast-glob` or `@next/eslint-plugin-next` release exists yet, and the package is a transitive development dependency, so it ships in no image (the console image carries only the `.next/standalone` trace). The only patterns it compiles are the repository's own ESLint globs — repository-controlled input, never untrusted data — so no principal is crossed. Revisit when a fixed release ships. |
| AR-09 | The ssh runner puts a command's merged env, secrets included, on the remote command line as `env K=V…` arguments, so another user of the remote host who reads its process table while the login shell and `env` start the command, or any `execve` auditing there, sees every value (CWE-214) | `RemoteCommandBuilder.build` and `buildReaping` (ssh runner, every command) | [ADR-0032](docs/adr/0032-ssh-runner-backend.md), amendment 2026-11-20 | **Interim; this row grants no exception to [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md) rule 7.** [#364](https://github.com/livesport/homer/issues/364) delivers the env as a sourced file and removes this row. Until then: the process-table read is bounded to the launch, because the shell `exec`s `env`, which `exec`s the command, so the values leave the process table once the command starts and remain only in its environment, which other users cannot read; Linux `hidepid=2` on `/proc` closes that read. `execve` audit records keep the argv for as long as the remote host retains them, under that host's root and outside Homer's control. The remote host and its other users are the operator's choice, outside Homer's principals; [`app/SERVER.md`](app/SERVER.md) tells operators to keep secrets out of `env` on multi-tenant hosts. Context only: many sshd configurations reject `SendEnv`, the ssh protocol's own env channel. |
| AR-10 | The Kubernetes runner passes a command's merged env, secrets included, as `env K=V…` arguments in the exec request's `command=` query parameters, so the request URI carries every value; Kubernetes audit events record `requestURI` at every level, `Metadata` included, so a cluster that audits `pods/exec` stores the values in its audit backend (CWE-598/CWE-532) | `KubernetesShellExecutor.cmd` env prefix, sent by `KubernetesApiExecClient` (Kubernetes runner, every command) | [ADR-0043](docs/adr/0043-k8s-sync-workspaces.md), [ADR-0045](docs/adr/0045-external-secret-delivery.md) | **Interim; this row grants no exception to [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md) rule 7.** [#364](https://github.com/livesport/homer/issues/364) delivers the env as a sourced file and removes this row. Until then: the reader is whoever can read the cluster's audit backend and any log pipeline it ships to. That reader is not a Homer principal, and caller-supplied `secret` inputs reach it along with operator env. The URI travels over TLS into no stored Kubernetes object, and [`app/SERVER.md`](app/SERVER.md) tells operators to scope the `pods/exec` audit policy. Inside Homer, a lost channel's step error and the exec client's failure log drop the exec URL and carry no cause or stack trace that quotes it; env values of at least 8 characters, raw and URL-encoded, are masked wherever else that text quotes them. A secret that must stay out of the URI already has a route: file delivery from cluster tooling, which Homer never sees (ADR-0045). |
| AR-11 | A component below `remoteWorkspaceRoot` can be swapped for a symlink between the ssh cleanup's per-component `lstat` checks and the `rm -rf` (or its SFTP fallback walk), which resolves the path again, so the sweep can delete a directory outside the workspace that the ssh user can write (same-UID TOCTOU) (CWE-59/CWE-367) | `SshRunnerSession.cleanWorkspace` (`rm -rf` over the exec channel, `WorkspaceSync.removeRecursively` fallback) | [ADR-0067](docs/adr/0067-ssh-cleanup-via-rm-rf.md) | No principal is crossed: the race needs a concurrent writer holding the ssh user's own UID on the remote host, a process the run left behind or another tenant of that account, which can already delete everything the sweep could reach. Closing it needs the removal anchored on a directory handle checked once, which neither `rm` on a path argument nor path-based SFTP operations provide. `remoteWorkspaceRoot` is checked at config load (absolute, normalized, not `/`); before the sweep the project root must also be at least two segments deep and below it. A symlink the `lstat`s find refuses the sweep, and the removal runs with the ssh user's own permissions. |
| AR-12 | A hard link or an ancestor directory swapped in between `readTextBounded`'s link check and its by-name `NOFOLLOW_LINKS` open makes the LangGraph status read a different regular file than the one it checked, at most 64 KiB, and report its `threadId`, `module` and `segment` when it parses as a run identity (same-UID TOCTOU; `NOFOLLOW_LINKS` binds only the final component and ignores the link count) (CWE-59/CWE-367) | `LocalFileOperations.readTextBounded`, called by `LangGraphRunStatusService.identity` (`GET /api/v1/processes/{id}/langgraph`) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-11-20 | No principal is crossed and nothing is gained: the race needs a concurrent local writer holding Homer's own UID, such as a local run's own code, which can already read any file the swap could lead to and write its content into `langgraph.json` directly. Closing it needs an `fstat` on the opened handle plus an `openat`-style walk for the ancestors, which `java.nio` does not expose portably. A final-component symlink fails the open, a FIFO swapped in is bounded by the open pool's timeout, the read stops at `MAX_IDENTITY_BYTES`, and the thread id it yields addresses only the run owner's checkpoint store ([ADR-0046](docs/adr/0046-owner-scoped-langgraph-checkpoints.md)). |
