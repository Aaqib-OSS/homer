# Security Policy

## Supported Versions

Only the latest release is supported with security fixes.

## Reporting a Vulnerability

Please report security vulnerabilities privately through GitHub's
**Report a vulnerability** form:
https://github.com/livesport/homer/security/advisories/new. Do not open
public issues for security reports.

There is no bug bounty program.

## Accepted risks

Weaknesses a scanner will legitimately keep reporting, which the maintainers
have consciously decided not to fix. Each row names the decision record that
argues the trade-off — the ADR is the authority, this table is the index.

Record a risk here **at the same time** as the decision, not when a scanner
first raises it: the security intake automation reads this file and
`docs/adr/` to avoid opening a ticket for something already settled. A new
row takes the next free `AR-NN` id; an id is never reused, so code can cite
it ([ADR-0117](docs/adr/0117-code-says-what-adrs-say-why.md)).

| AR-01 | The output cap counts kept bytes, not raw process output: a command whose output is entirely dropped by `claudeDropSystemSubtypes` cannot trip `maxOutputBytes` (CWE-770, CVSS 5.3) | `LineFilteringOutputStream`, all four `ShellExecutor` backends | [ADR-0063](docs/adr/0063-filter-claude-stdout-at-write-time.md) | The run stays bounded by its `timeout` and the filter's memory is constant, so the failure mode is bounded CPU and I/O rather than exhaustion. | AR-02 | A Claude session with more than 1 000 model calls is charged the spend endpoint's best figure observed at poll time while its later calls remain unpriced, so the recorded cost can understate actual spend (CWE-693/CWE-400, CVSS 2.3) | `LlmHarnessExecutor.accountAttempt` capped-poll branch | [ADR-0061](docs/adr/0061-price-claude-runs-from-session-spend-endpoint.md), amendment 2026-09-16 | Every session figure priced from a capped poll is forced to an `incomplete:` `fallbackReason`, visible in the status API and spans, so the under-count is never silent, and no path charges below the best session figure observed. Lifting the cap would let crafted stdout drive the full poll schedule. Reaching the path needs an authenticated Claude run and favorable ingestion lag. |
| AR-04 | An ancestor directory of a packed file can be swapped for a symlink between the pack walk's containment check and `addFile`'s by-name open, so a file outside the upload root can enter a downloaded archive (same-UID TOCTOU; `NOFOLLOW_LINKS` binds only the final component) (CWE-59/CWE-367, CVSS 2.3) | `TarStreams.addDirContents` + `TarStreams.addFile` (pack path, all transports); `WorkspaceSync.uploadDirInto` + `uploadFile` (ssh SFTP upload) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-09-23 | No principal is crossed: the race needs a concurrent writer holding the runner's own UID, which can already read every file it could disclose. Closing it needs an `openat`-style dirfd walk plus an `fstat` on the opened handle, neither of which `java.nio` exposes portably (ADR-0047 rule 6). Escaping symlinks are skipped, the walk descends on the checked realpath, hard links are skipped, so the exposure is confidentiality-only at the runner's own UID. |
| AR-05 | A target or ancestor directory of an extracted file can be swapped for a symlink between the extract walk's containment check and its by-name open, so sync-down can write a file outside the workspace (same-UID TOCTOU; the directory branch must follow contained links) (CWE-59/CWE-367, CVSS 5.8) | `TarStreams.extractEntry` directory branch (Kubernetes sync-down, external-runner tar download) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-09-30 | No principal is crossed: the tar stream cannot create links (link entries are skipped), so the race needs a concurrent writer holding Homer's own UID, which can already write every file it could reach. | AR-06 | A single-file download's target can be swapped for a symlink between the `NOFOLLOW_LINKS` write and the mode normalization, which the JDK applies to the link's destination even through a `NOFOLLOW_LINKS` view, so the destination's mode becomes `0755` or `0644` (same-UID TOCTOU) (CWE-59/CWE-367) | `TarExtraction.extractEntry` single-file branch (Kubernetes and external-runner single-file download) | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-11-05 | No principal is crossed: the race needs a concurrent writer holding Homer's own UID, which can already change the mode of every file the link could lead to; the write itself still refuses a link. Closing it needs an `fchmod` on the write's descriptor, which `java.nio` does not expose; creating the file with its final mode is defeated by the umask and by an overwritten file keeping its mode. |
| AR-07 | A caller cancelled while a LangGraph inspect/state interpreter runs keeps its permit, the child and its readers until the child exits or the 15 s timeout fires, because the wait is one blocking `waitFor` (CWE-772, CVSS 5.3) | `runBoundedGraphSubprocess` (`ProcessGraphInspectRunner`, `ProcessGraphStateRunner`) | [ADR-0073](docs/adr/0073-langgraph-topology-is-structured-data.md), amendment 2026-10-09 | Cancellation gives no amplification: an uncancelled caller holds the same single permit and interpreter for the same bounded time. | AR-08 | A deeply nested brace pattern exhausts the stack while `braces` compiles it, so whoever shapes a glob pattern can stall the process (CWE-674, CVSS 8.7) | `braces` 3.0.3 ← `micromatch` 4.0.8 ← `fast-glob` 3.3.1 ← `@next/eslint-plugin-next`, dev-only lint toolchain | [ADR-0088](docs/adr/0088-dependency-check-on-the-nvd-mirror.md), amendment 2026-10-17 | No patched `braces`, `micromatch`, `fast-glob` or `@next/eslint-plugin-next` release exists yet, and the package is a transitive development dependency, so it ships in no image (the console image carries only the `.next/standalone` trace). The only patterns it compiles are the repository's own ESLint globs — repository-controlled input, never untrusted data — so no principal is crossed. Revisit when a fixed release ships. |
| AR-11 | A component below `remoteWorkspaceRoot` can be swapped for a symlink between the ssh cleanup's per-component `lstat` checks and the `rm -rf` (or its SFTP fallback walk), which resolves the path again, so the sweep can delete a directory outside the workspace that the ssh user can write (same-UID TOCTOU) (CWE-59/CWE-367) | `SshRunnerSession.cleanWorkspace` (`rm -rf` over the exec channel, `WorkspaceSync.removeRecursively` fallback) | [ADR-0067](docs/adr/0067-ssh-cleanup-via-rm-rf.md) | No principal is crossed: the race needs a concurrent writer holding the ssh user's own UID on the remote host, a process the run left behind or another tenant of that account, which can already delete everything the sweep could reach. Closing it needs the removal anchored on a directory handle checked once, which neither `rm` on a path argument nor path-based SFTP operations provide. `remoteWorkspaceRoot` is checked at config load (absolute, normalized, not `/`); before the sweep the project root must also be at least two segments deep and below it. A symlink the `lstat`s find refuses the sweep, and the removal runs with the ssh user's own permissions. |
| AR-12 | A hard link renamed over `langgraph.json` or a watched run's stdout between `readTextBounded`'s link check and its by-name `NOFOLLOW_LINKS` open, or a symlink swapped in for the artifacts directory between its check and that open, makes Homer read a different regular file than the one it checked, at most 64 KiB; when it parses as a run identity, the status endpoint reports its `threadId`, `module` and `segment` and a resume continues its thread, and a firing continuation delivers it as the watched run's result. The artifact download, the log tail and the LLM-event stream check the artifacts directory only when they resolve the path and open the file later (a stream at the first poll that finds it, as late as the stream's end), so a symlink swapped in for the directory in between is followed and the caller is served the file it leads to. A symlink at the run root or a directory above it is followed by every one of these reads with no race at all (same-UID; `NOFOLLOW_LINKS` binds only the final component and ignores the link count) (CWE-59/CWE-367) | `LocalFileOperations.readTextBounded`, called by `LangGraphRunStatusService.identity` for `GET /api/v1/processes/{id}/langgraph` and `POST /api/v1/processes/{id}/resume`, and by `ContinuationFireService.extractResult` when a continuation fires; `ArtifactService.resolveArtifactPath`, then `LocalFileOperations.streamFile` (artifact download); `LogTailService.resolve`, then `tail`; `LlmEventStreamService.resolve`, then `followFile` | [ADR-0047](docs/adr/0047-security-by-design-and-threat-model.md), amendment 2026-11-20 | No principal is crossed and nothing is gained: each case needs a local writer holding Homer's own UID, such as a local run's own code, which can already read any file the swap could lead to and copy its content into the run's own files directly. Those files are agent-written, so their content is attacker-chosen by construction (ADR-0047 rule 2), and a swap only changes where it comes from. Homer acts on an identity read, but both callers keep the thread id inside the run owner's checkpoint store, so neither the status read nor the resumed run reaches another principal's checkpoints ([ADR-0046](docs/adr/0046-owner-scoped-langgraph-checkpoints.md)); a continuation's result is the watched run's own output, which that run could have written anyway, and a download or stream answers only a caller who may already see the run. Closing the races needs an `fstat` on the opened handle plus an `openat`-style walk, which `java.nio` does not expose portably, and re-checking the directory at each poll would only narrow the streams' window; checking the run root and above needs the configured workspace root, which an operator may reach through a symlink, so a stored artifacts path cannot be compared with it lexically. A symlinked artifacts directory found at resolve, or a symlinked `langgraph.json` or stdout file, is refused, as is a recorded stdout path outside the artifacts directory, and the read stops at `MAX_IDENTITY_BYTES` or the 64 KiB inline-result cap. A FIFO swapped in bounds only the caller's wait, by the open pool's timeout: the blocked open keeps one of the pool's 8 threads, and once all 8 are held every file read through the pool fails at once for every caller. |
| AR-13 | A step's env file can outlive its step, because its removal is best effort. The executor's own removal can fail (a lost SFTP session, an exec refused on a dead pod) and is then only logged by path; Homer can be killed between the file's upload and the command sourcing it; on Kubernetes the kubelet can kill the container (OOM, deadline) before its first line removes the file. On ssh, the session's workspace removal runs only when the agent's `cleanAfterFinish` is true and there is no startup sweep, so with `cleanAfterFinish: false`, or a failed removal, the file stays until an operator removes the project root. The file holds the step's env, secrets included, at mode `0600` in a `0700` directory (CWE-459, CWE-532) | `SshShellExecutor.cmd`, `KubernetesShellExecutor.cmd` (the env file's remove-on-failure scope), `RemoteShell.envFileContent` (its first line removes the file) | [ADR-0032](docs/adr/0032-ssh-runner-backend.md), [ADR-0043](docs/adr/0043-k8s-sync-workspaces.md), amendments 2026-11-21 | Only a reader already holding the runner's own UID, or root on the host or node, can open the file, and either of them can already read the environment of the step's processes and the workspace it ran in, so no principal is crossed. The command's shell unlinks the file as its first line, and a refused exec, a timeout, a cancellation and a non-zero exit remove it from the executor under its own bounded deadline, best effort. A kept workspace already holds the step's data and files at the same UID, so the leftover adds no reader. Closing the remaining case needs a kill-proof remover on the remote side, which neither sshd nor the kubelet offers. Where a workspace or pod is removed, the file goes with it (the ssh session-end `rm -rf` of the project root; the pod's deletion on Kubernetes, at once or after `keepPodTtlSeconds` for a kept pod); the startup sweep needs no name pattern for it, since Kubernetes deletes whole pods and ssh has none. |
